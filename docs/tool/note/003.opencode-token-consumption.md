## 概述

OpenCode 提供 Go 订阅与 Zen 按量付费两种消费模式，并有一批免费限免模型。本文整理各模式的计费方式、模型单价、请求量估算与省钱建议，数据来自 OpenCode 官方文档（2026 年 8 月）。模型与价格可能随官方调整而变化。

## 一、消费体系总览

| 模式 | 计费方式 | 说明 |
|------|----------|------|
| **Go 订阅** | 月费 $10，按美元额度扣除 | 包含约 $60 额度（6 倍回报） |
| **Zen 按量付费** | 按 token 实际消耗扣费 | 充值余额，用多少扣多少 |
| **免费模型** | 不扣费 | 限免活动，有次数/频率限制 |

## 二、Go 订阅消费规则

### 基础信息

- **月费**：$10（首月 $5 优惠，不定期）
- **额度目标**：$10 月费对应约 $60 的 token 消费额度（6 倍回报）
- **可选**：启用 `Use balance` 后，额度用尽可自动切换到 Zen 余额

### 额度周期限制

| 周期 | 额度上限 |
|------|----------|
| 5 小时 | $12 |
| 每周 | $30 |
| 每月 | $60 |

### Token 计算方式

```text
消耗金额 = (输入 token 数 x 输入单价 + 输出 token 数 x 输出单价 + 缓存读取数 x 缓存单价) / 1,000,000
```

不同模型单价不同，便宜模型能打更多次。

## 五、影响消费的关键因素

### 5.1 上下文长度

- 上下文越长，输入 token 数越多，消耗越大
- 部分模型在超长上下文时单价翻倍（Grok 4.6、GPT 5.6 Luna、Qwen3.6/3.7 Plus、DeepSeek V4 Pro/Flash）

### 5.2 高峰/低谷（DeepSeek 专属）

| 时段 | 类型 |
|------|------|
| 01:00-04:00 UTC、06:00-10:00 UTC（周一至周五） | Peak（高价） |
| 其他时段 + 周末 | Off-Peak（低价） |

### 5.3 缓存命中

- **Cached Read**：相同上下文再次请求时，缓存部分按更低价计费
- **Cached Write**：首次缓存写入时按较低价计费
- 缓存命中率越高，实际消费越低

### 5.4 模型选择

- 同一任务用便宜模型（如 MiMo-V2.5）比贵模型（如 Kimi K3）消耗低几十倍
- 贵模型不一定适合所有任务，轻量任务选便宜模型更划算

## 六、消费管理

### 查看用量

```text
opencode    # 在 TUI 中运行
/connect    # 连接账户
/auth       # 登录查看详细用量
```

### 设置月度限额

在 Zen 控制台中设置整月用量上限，到上限后自动停止消费。

### 省钱建议

1. **默认用便宜模型**：日常编码用 MiMo-V2.5、LongCat-2.0 等
2. **复杂任务切贵模型**：重度重构/架构时用 Kimi K3、Qwen3.8 Max
3. **利用缓存**：保持上下文一致性，提高 Cached Read 命中率
4. **选对时段**：DeepSeek 模型在 Off-Peak 时段半价
5. **Go 额度用完**：用 Zen 免费模型继续工作
